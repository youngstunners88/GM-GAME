# Sentinel hardening backlog — findings verified, NOT yet applied

Kimi (`docs/model-responses/2026-08-11-kimi-false-pass-hunt.md`) was asked one
question: which checks report PASS for the wrong reason? That failure mode
matters more than a missed vulnerability, because in a report a vacuous pass is
indistinguishable from real safety.

**Nothing here has been applied.** `scripts/security-sentinel.sh` is a live
deploy gate and the founder's instruction for this pass was explicitly "do not
overwrite existing security-sentinel" and "soft follow-ups only". Editing a
blocking gate unprompted, at the end of a pass, is how a green build turns red
for reasons nobody asked for. These are queued for a greenlight instead.

Every claim below was checked against the actual repo rather than taken at face
value — and **three of Kimi's four headline claims did not survive that check.**

## Refuted — verified against this repo, claim does not hold

| Claim | Verification | Verdict |
|---|---|---|
| `DEP-003` vacuously passes because `web/game` is gitignored and absent | `git ls-files web/game` returns **13 tracked files**; the export output is committed | **REFUTED** |
| `SEC-004` / `INJ-001..004` vacuously pass because `src/` may be empty | `git ls-files 'src/**/*.gd'` returns **110 files** | **REFUTED** |
| `SEC-002`'s regex misses `.env.local` | `printf '.env.local' \| grep -qE '^\.env($\|\*\|\.)'` **matches** — grep is not anchored at the end, so the `\.` alternative covers every `.env.<suffix>` | **REFUTED** |
| `INJ-002` misses `Expression()` shorthand | GDScript has no such shorthand; `RefCounted` types require `.new()` | **REFUTED** |

## Standing — real, low severity, worth doing on greenlight

| ID | Gap | Why it is real | Cost |
|---|---|---|---|
| `SEC-003` | "`.env` never committed" queries only the three literal names `.env`, `.env.local`, `.env.production`. A committed `.env.backup`, `.env.staging` or `.env.secret` is invisible. | The check's title claims coverage of a family; the query enumerates three members of it. Widening the `git log` pathspec to `.env*` can only ever find MORE, never fewer — a strictly safe change. | one line |
| `CI-003` / `CI-004` | Absence of `.gitleaks.toml` / `.gitleaksignore` records **PASS** ("no allowlist file"). | Weaker than Kimi framed it — with no allowlist there genuinely is no scope creep, which is what the check measures, and the evidence string already discloses the absence to anyone reading. But "the file is missing" and "the file is narrow" are different states sharing one status, and the sentinel has no SKIP concept to separate them. Both files currently exist, so this is dormant. | needs a SKIP status, which changes the `18/18` contract CI and STATUS both report — not a drive-by |
| `INJ-004` | Only ALL-CAPS identifiers are accepted as compile-time constants, so `FileAccess.open(SavePath, …)` on a mixed-case const would be flagged. | A false **positive**, not a false pass. Nothing in the tree trips it today, and a scanner that cries wolf trains people to ignore it — so it is worth fixing, but it is not a safety hole. | small |

## The principle, which was applied elsewhere this pass

The same class of bug was found and fixed in the **checklist** scanner during
this pass: three checks (`SEC002`, `AUTH001`, `LOG003`) used rule shapes the
scanner had no handler for and were silently reported as skips. That catch-all
now reports a **failure**, because a rule that cannot be executed is not a rule
that does not apply.

If this backlog is greenlit, apply the same rule to the sentinel: absence of a
thing to scan must be reported distinctly from having scanned it and found
nothing.

# Checklist backlog — the glob gap (measured, NOT applied)

Found by qwen3.7-max auditing the scanner (`docs/model-responses/2026-08-11-qwen-scanner-integrity.md`).

`globMatch` compiles `*` to `[^/]*`, so **`*.js` matches only top-level files**.
Every rule in the pack uses top-level globs. On a repo where the code lives in
`src/`, `web/` and `backend/`, that means those rules were opening almost
nothing — including `SEC001`, the critical secrets grep, which also never
listed `*.gd` at all.

Concretely: the checklist's eval/dynamic-execution rule was never scanning
`web/web3.js`, which Grok independently ranked as the **second most exploitable
surface in the project**. The sentinel covers that ground with GDScript-aware
greps (INJ-001..004), which is exactly why both scanners exist — but the
checklist's coverage was narrower than its labels implied.

## Measured effect of broadening `*.x` → `**/*.x`

Trialled on a scratch copy of the rules, with generated output excluded
(`web/game/**` is Godot export output, regenerated by CI, not authored):

| | current | broadened |
|---|---|---|
| pass (examined a file) | 11 | **25** |
| fail | 0 | **3** |
| skip | 34 | 17 |

**All three new failures are false positives**, which is why this is queued
rather than shipped:

| Rule | Matched | Reality |
|---|---|---|
| `AUTH002` "no client-side auth checks" | `web/launcher.js:469` — `if (isMobile && !isLandscape && window.innerWidth < 400 …)` | a mobile orientation check; no auth anywhere near it |
| `AI001` "no eval / dynamic code execution" | `web/web3.js:4` — a **comment** reading "autoload calls … via JavaScriptBridge.eval"; and `scripts/security-audit.ts:12` — `import { spawnSync }` in the shim | a comment and an import statement |
| `PLAT006` "remote control channels need strong auth" | `backend/email_templates.js:110/189/207` — `${cta(base, "share_rank", …)}` | share buttons in an email template |

Shipping this as-is turns a blocking deploy gate red on three things that are
fine. A scanner that cries wolf teaches people to skip it, which costs more
than the coverage gains.

## What applying it properly requires

1. Broaden the globs (`**/` prefix) and exclude generated output.
2. Then tune the three rules above: `AUTH002` needs to require an auth-ish
   identifier in the match, not any `if`; `AI001` needs to ignore comments and
   `import` statements; `PLAT006` needs to not treat template interpolation as
   a command channel.
3. Add `*.gd` to `SEC001`'s file list so the checklist's secrets grep covers
   GDScript directly rather than leaning entirely on the sentinel.

Worth doing — it is the difference between 11 rules that looked at something
and 25. It is a focused pass of its own, not a drive-by at the end of another.
