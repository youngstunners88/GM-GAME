## Decision Gates

**Gate 1 — after art integration: "Does the game look finished?"**
Currently *cannot be answered*. The four Smoke Lounge slots and all nine
Blaze Rush images are still placeholders. Blaze Rush itself no longer looks
like programmer art, and the Smoke Lounge now has the real soundtrack — but
the branded content that would make it read as *this client's* game is the
missing piece. **Blocked on the asset handoff, not on work.**

**Gate 2 — after playtest: "Is v1.2 fun enough to show people?"**
Not yet evaluated end-to-end. Every section has been verified in isolation
(campaign 5/5, shooter 6/6, Smoke Lounge walk, Blaze Rush run, torch throw),
but nobody has played Stage 1 → Lounge → Blaze Rush → Stage 2 as one
continuous session. That's item 6 above and it's the honest prerequisite for
answering this.

**Gate 3 — after tag: "Ready for Base44/marketing?"**
Answer remains **wait for 50+ players.** Unchanged.

## How to use this doc in a self-directed session

Work top-down through **Remaining**, skipping anything in the blocked block
whose asset still hasn't arrived (check `docs/ops/asset-handoff.md` first —
if a path listed there now has a real file, that item is unblocked and
should be done immediately, since the integration points already exist).

Do not start anything under **Explicitly deferred** without the client
saying so in that session.

Standing rules that apply to every session regardless of what this doc says:
all 8 gates green before commit; STATUS.md updated; never claim something
was verified that wasn't; investigate before building, because prompts have
repeatedly described a repo state that doesn't match reality.
