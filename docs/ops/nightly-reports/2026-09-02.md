## 2. New measured fact (this changes how we read a whole class)

I built a gate to reproduce the "coroutine after free" class on `melt_forge.gd`
(`await create_timer(10s)` then `particles.queue_free()`), freeing the forge mid-await.

**It did not reproduce.** Godot 4.3 **abandons** a coroutine when its owning object is freed —
the line after the `await` simply never runs. So this class is a *silent skip of that line*,
**not** a dangling-pointer crash. And here the skipped line only frees a **child** of the forge,
which freeing the parent already did.

Consequences, both applied:
- Severity downgraded CRITICAL/HIGH → **MEDIUM**, reworded to "logic after `await` may be
  silently skipped" — it's only a bug when the skipped line mattered *outside* the node.
- Recorded in `gm-nightly-hardening` so no future run re-litigates it.
- **The gate was deleted.** All three of its assertions passed trivially; a gate that cannot fail
  is worse than no gate (this project has already shipped one of those).
