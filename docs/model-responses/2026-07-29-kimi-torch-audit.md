## Task 2 — Lifetime / leak

- **med — flame_projectile.gd:87-98 — the fizzle branch in `_despawn()` is inverted relative to its own comment, and it fires on the impact path.** `_impact()` (impact SFX + `_spawn_burst(16)`) falls through into `_despawn()`, where `_age < lifetime - 0.05` is true for essentially every impact (impacts happen mid-flight, well before 1.35s). Result: every impact *also* plays `torch_fizzle` and spawns a second `_spawn_burst(10)` — 26 particles and two SFX per hit. Conversely the actual timeout path (timer fires at `_age ≈ 1.4 ≥ 1.35`) skips the fizzle entirely, so a full-flight flame despawns silently despite the comment saying that's the fizzle case. Today the audio half is masked (SFX assets absent → `play_sfx_at` no-ops per ground truth), but it becomes an audible double-play the moment assets land. Fix: gate the fizzle on "not impacted" (a flag set in `_impact()`), or move the fizzle into the timer callback.
- **low — flame_projectile.gd:121-123 — orphaned burst node if `current_scene` is null.** `burst` is created via `CPUParticles2D.new()` *before* the `root == null` early return; on that path it is never added to the tree and never freed → small one-off leak. Only reachable during a scene transition at the exact frame of impact.
- **info — scene-change mid-flight is clean.** The projectile is a child of `current_scene` (combat_handler.gd:99), so it's freed with the scene; the `SceneTreeTimer` connection to `_despawn` auto-disconnects on free (no call-into-freed-object). - **low — flame_projectile.gd:69-78 — same-frame double-`_impact()` is possible.** `queue_free()` is deferred, so if `body_entered` and `area_entered` both fire in one physics step, `_impact()` runs twice (double burst/SFX).
