## Investigation first — a working audio pipeline already existed

The session prompt's Workstream A proposed a raw one-off `curl` command
against ElevenLabs' sound-generation endpoint. The repo already has a
proper, documented, data-driven pipeline: `scripts/generate_audio.py` +
`assets/audio-manifest.json`, backed by `.claude/skills/game-audio-forge/
SKILL.md`'s own prompt-engineering rules (era/medium first, one event per
sound, envelope over source description, explicit duration discipline).
Used that instead of reinventing it. Checked what was actually missing
before generating anything:
- `torch_throw`/`torch_impact`/`torch_fizzle` — referenced in
  `flame_projectile.gd` since the previous session, but the files were
  never generated (silently no-op'd via the established missing-asset
  convention).
- `tax_alert` — the Tax Collector's ALERT-state telegraph had zero audio
  feedback; genuinely missing, confirmed by grepping the whole file for any
  `AudioManager` call (none existed).
- `smoke_lounge.mp3` — still absent from the repo (checked twice now across
  two sessions). ElevenLabs' sound-generation endpoint doesn't produce full
  music, but a ~20s ambient soundscape is squarely its normal use case;
  extended the manifest/generator with a `music` category (same endpoint,
  longer duration, different output directory) rather than writing a
  separate one-off script.
- Also checked whether boss-hit feedback was really "missing" as the prompt
  claimed: `axe.gd`'s impact already plays a generic `hit` SFX on any enemy
  contact including bosses, and boss phase transitions already fire a VO
  line (`_phase25_0`/`_phase50_0` files already exist per boss). Both
  reasonably covered already; skipped adding a redundant boss-specific
  grunt to avoid scope creep on an already-served event.

All 5 genuinely-missing assets generated via the real pipeline in one
pass, all distinct audio (verified by hash, not just byte count, since the
three torch SFX happened to come back the same file size).

## Implementation

- **SFX wiring**: one new line in `tax_collector.gd` (play `tax_alert` on
  the PATROL→ALERT edge). The three torch keys and the Smoke Lounge ambient
  call were already wired from prior sessions — generating the files was
  the whole remaining gap.
- **Blaze Rush visual pass** (`src/dashmode/blaze_rush.gd`): 3-layer
  background (static void, true `ParallaxBackground` haze with
  `motion_mirroring` so it tiles over a multi-thousand-pixel course, and
  two camera-attached `CPUParticles2D` "speed atmosphere" emitters), a
  player speed trail, retinted obstacles per a warm=hazard/cool=safe/
  cream=collectible glance-test rule, a candle ember particle, a smoke-token
  idle pulse + pickup burst, and a single reusable hazard-telegraph bar that
  repositions each physics frame to whichever lethal hazard (candle or
  floor gap) is next ahead of the player, fading in over a 450px lead
  distance.
- **Asset placeholders** (`src/level/secret_realm.gd`): the session prompt
  asked for a new generic `AssetSwapper` autoload with a register/swap-by-
  key API. Built something narrower instead — `_swap_placeholder_texture()`,
  a single helper called at the four already-known Smoke Lounge placeholder
  sites (three logo slots + the founder mural), each just a
  `ResourceLoader.exists()` check. No registry, no autoload — four known
  call sites don't justify one. Real art drop-in still needs zero code
  changes; it just needs the file at the documented path.
- **`docs/ops/publishing.md`** (new): documents the existing
  `scripts/deploy_itch.sh` command per the session's hard rule ("document
  even if you don't run it"). Did not run a manual itch.io push this
  session — CI already auto-deploys via `butler` on every push to `master`
  when the `BUTLER_API_KEY` repo secret is set, and the `ITCH_API_KEY`
  present in this sandbox is a session-local credential, not confirmed to
  be the same GitHub Actions secret. Pushing to the live public game page
  from an unconfirmed credential is exactly the kind of hard-to-reverse,
  externally-visible action that needs explicit confirmation rather than
  inferring permission from a written brief.
