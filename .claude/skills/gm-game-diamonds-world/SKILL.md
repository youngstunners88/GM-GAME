# The Pressure Study — world design

Read [runtime contract](references/runtime-contract.md) before edits and [region brief](references/region-brief.md) before art direction. Read only this region’s source images unless comparing the three worlds.

1. **Ground the current build.** Inspect recent commits and the actual scene, map bounds, layer order, camera and existing assets. Reproduce the reported empty view when runtime tools are available. Diagnose opaque occluders before treating the problem as missing art.
2. **Extract the reference language.** Inspect founder document images 05–10; record material, architecture, light and circulation cues. Preserve the existing characters and factual content. Apply the region brief to original map assets.
3. **Author the map contract.** Preserve stop IDs; mark arrival, return, hero, paths, interaction clearances, occluders and decorative-only boundaries in a machine-readable layout. Treat existing coordinates as anchors, not arbitrary art-placement suggestions. Show the plan and target before expensive production.
4. **Build a material world.** Establish readable continuous ground, district transitions and structures. Give each learning stop a meaningful architectural setting. Use a loop with short spurs so revisiting is easy. Keep the examiner recognizable from the main route.
5. **Add region atmosphere.** Use sparse cyan glints and low-contrast water motion. Keep sparkle off quiz text and avoid a neon cyan veil over the terrain.
6. **Produce assets only through the available authorized pipeline.** Follow the provider routing and approval rules in the runtime contract. Prepare isolated prop briefs and sprite/texture budgets first. Track generation, cleanup, import and runtime inspection as separate states.
7. **Integrate and review.** Keep decoration modular and below actors. Verify the whole study/test/ascent journey in all three protocols after shared code changes. Produce before/after captures, record remaining defects and install no unverified art into a live build.

Deliver a region layout, prop briefs, provenance, concrete code/assets when authorized and available, and a concise evidence-based status. Do not describe a skill or a concept as a redesigned live world.
