# Performance guide and identity lock

Read design/ep2/motion/TRANSCRIPT_ADAPTATION.md and the archived WORKFLOW_TRANSCRIPT.txt.
The guide owns performance/timing; the approved reference owns identity. A reference still is not an observed motion.

## Prepare one action

- Give each guide an immutable source ID/path, provenance/rights, frame rate, frame range, actor target, camera, full-body visibility and source digest. Prefer the current licensed project clips, owner performances, or locally keyed Blender clips.
- Pin one global character description and approved full-body reference. State functional details: Bull's horns/hat/cigar/coat/free hands/rifle, bear anatomy/claws/bow, glove/contact surfaces and which hand does what. Inspect autogenerated captions; do not introduce missing props or swap founder identity.
- Specify phase events: anticipate, move, settle; for objects: approach, touch/grip, act, release. Track planted feet, gaze, support, force direction and the action's purpose.
- Review a manageable shot. The transcript's 12 s starting range, 7 s diagnostic range and ~0.5 MP setting are video-generation suggestions, not Godot clip durations or guarantees. A grip/draw/pull action may be much shorter.
- For split guides, the transcript passes 17 frames of context. Record the actual guide FPS and overlap duration; align overlap poses/velocities without playing duplicated time. Do not assume 17 frames means 17/30 s or that it prevents hidden costume drift.
- Keep appearance/prompt/reference global unless an action truly requires an override. Label which settings came from a connected input, since connected values can override planner UI fields.

## Select the correct subject

A plain-language target is not a hard mask. With Bull, bears and Lil Blunt in one guide, preview the actor track and reject unintended subject replacement.
Start with the simplest unmasked full-frame comparison for optional video swaps. Add a mask only to solve a specific selection/background problem; compare seams, clipped hands/horns/costume, temporal stability and movement with the unmasked result.
For retargeting, prefer an isolated actor performance with hands/feet visible; don't mistake a full-frame generator output for a clean skeleton source.

## Audio

Preserving the video's soundtrack only muxes audio. Audio-driven generation/lip sync needs the appropriate audio input/encoder and explicit conditioning; the transcript calls out an audio VAE plus with-audio in BFS shot H3 conditioning. This setup has not been verified here.
For the game, voice playback, mouth/jaw animation and timeline events are separate outputs. Our current 24-bone rigs have no articulated fingers; inspect jaw/face capability too before promising lip sync.
Do not regenerate voice/music to repair body motion. Keep dialogue event timings, and record when no face animation is available.

## Alternatives and boundaries

No licensed guide available: author a phase-based clip in Blender and label it authored, not captured.
For local authoring, performance.source_path may name a reviewed timed action/keyframe recipe; it need not be a finished animation. Declare it owner-authored and resolve the phases before the input-readiness gate. This avoids requiring an exported clip before authoring it.
BFS/ComfyUI unavailable: use existing approved clips/local authoring; do not fabricate a LoRA result.
Generated guide video, if used, still needs license-cleared motion extraction, anatomy/rest-aware retargeting and prop-contact authoring. The transcript warns about animal/non-human anatomy and commercial model terms; inspect the actual model page before use. The cited Motion2MixamoRig extraction stack is not automatically a commercial-safe substitute.

Review guide, approved reference and candidate together, then hand timing/contacts to ep2-rest-aware-retargeting and ep2-prop-contact-animation. Change one variable at a time with the same seed/camera/input. Do not train an RL reward loop merely because the transcript describes it as future research.
